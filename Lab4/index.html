Templates and Classes That Own Memory

Write code once for any type with function and class templates. Then the classes that own memory: what must happen when they're copied, assigned, and destroyed (the rule of three), for an array and for a chain of nodes, and how exceptions and RAII keep that memory safe. Every array-based and linked container you'll write in CSS 342, the course this lab supports, is a class template that needs all of this.

Templates

generic code, what T must support, templates live in headers
Lecture

Generic code

15 min

A stack of int values, a stack of strings, and a stack of Student objects differ only in the type of item they hold, and writing (and fixing) three copies of the same code is wasteful and error-prone. A template lets you write the code once with the type as a parameter; the compiler produces a version for each type you use. That is how the standard library gets vector<int> and vector<string> from one definition, and how the containers in your CSS 342 textbook, like ArrayBag<ItemType>, are written.

  • Function template: write the function once with a type parameter T. For each type you call it with, the compiler instantiates (writes) a real function. T is usually deduced from the arguments; maxOf<double>(3, 4.5) names it explicitly. 
    template <typename T>                  // one type parameter
T maxOf(T a, T b) { return (a < b) ? b : a; }

template <typename A, typename B>      // two type parameters
void showBoth(A a, B b) { cout << a << " | " << b << endl; }

template <typename R, typename T>      // R is only the return type: can't be deduced
R convertTo(T value) { return static_cast<R>(value); }

maxOf(3, 7);                           // deduced: T is int
maxOf<int>(3, 7);                      // explicit: the same maxOf<int>
maxOf<double>(3, 4.5);                 // explicit: 3 becomes 3.0 (maxOf(3, 4.5) won't compile)
showBoth<double, string>(42, "apples"); // both named
showBoth<char>(65, 2.5);               // A named (char: prints A), B deduced (double)
convertTo<int>(3.99);                  // R must be named; T deduced: 3
    Example: 1.1.template_variations/templates.cpp runs all of these; its README.txt has the output and the errors for maxOf(3, 4.5) and convertTo(3.99).
  • What T must support is whatever the body uses: maxOf and a sort need <, printing needs <<. Your own classes work once they have those operators (Lab 2, Part 4).
  • Class template: template <typename T> class Box { ... };, used as Box<int>: you always name T. Each member defined outside the class repeats the template line: template <typename T> T Box<T>::get() const { ... }. A friend operator<< must be a template with its own parameter, template <typename U> friend ostream &operator<<(ostream &, const Box<U> &);, so cout << a binds U to int; written like a normal class's friend, it compiles with a warning and fails to link. Example: 1.2.class_template/box.cpp (README.txt).
  • The standard library is full of class templates: vector<int> is a growable array of ints that knows its size (push_back, size(), []), and vector<string> is the same template with a different T. Even string is one underneath: it's short for basic_string<char>. The last four lines of main in example 1.2 use a vector<int>.
  • Templates live in headers. The compiler needs the full definition wherever the template is used, so you can't compile it separately in a .cpp: the files compile, but the link fails with undefined reference. Example: 1.3.template_in_cpp splits example 1.2's Box into box.h and box.cpp; its README.txt shows the link error, why, and the fix.
  • Reading template errors: the error points inside the template; find the required from here line that points at your code.
Coming from JavaJava generics only work with objects (ArrayList<Integer>) and are checked once. C++ templates work with any type, including int, and generate separate code for each type you use. vector is C++'s ArrayList.
In your CSS 342 courseCarrano's ArrayBag, LinkedBag, LinkedStack, and Node are all class templates, defined entirely in their headers. Exercise 1 turns a working class into a class template, the same step that gets you from an int-only container to Carrano's.

The rule of three

ownership, shallow vs. deep copy, copy constructor, operator=
Lecture

Copies of a class that owns memory

20 min

In C++, copying an object is the default: passing by value, returning, and = all make copies. For most classes the compiler-written copy is right, but for a class that owns memory through a pointer it copies only the address, leaving two objects that share one block of memory and both delete it. Every CSS 342 container that uses new needs its own copy rules, and this part shows how to write them.

  • Shallow vs. deep copy: copying a pointer copies the address it holds, not what it points at. A shallow copy (int *shallow = original;) leaves two pointers to one array: a change through one shows up through the other. A deep copy gets its own memory (new) and copies the values into it: a different address, and changes stay separate. Example: 2.1.shallow_vs_deep/copies.cpp copies a 4-element array both ways, sets original[0] = 99, and prints each pointer's address and values (README.txt): 
    original points to 0x238efeb0: 99 20 30 40
shallow  points to 0x238efeb0: 99 20 30 40
deep     points to 0x238efed0: 10 20 30 40
  • Ownership: a class that allocates memory in its constructor owns it and releases it in its destructor. That's half of a correct class.
  • The compiler writes a copy constructor and an operator= for you if you don't. They copy each member, so a pointer member is copied as an address: both objects point at the same memory (a shallow copy). A change through one shows up in the other, and both destructors delete the same memory: a double free. Example: 2.2.shallow_copy/shallow.cpp crashes exactly this way; its README.txt has the output and the picture.
  • Copy constructor or operator=? The copy constructor makes a new object: IntArray b = a;, IntArray b(a);, passing or returning by value. operator= runs on an object that already exists (and already owns memory): c = a;.
  • operator= in four steps: do nothing for self-assignment (a = a: check this != &other); copy the other object's data into new memory; release the old memory; and return *this; so c = b = a chains.
  • The rule of three: if a class needs a destructor, it needs a copy constructor and a copy assignment operator too. Example: 2.3.rule_of_three/three.cpp is example 2.2's Numbers, the same class, done right: it adds a deep-copying copy constructor and operator=, runs the same b = a; b.set(0, 99); (now a keeps 10), and prints which one runs (README.txt).
  • Or forbid copying: Numbers(const Numbers &) = delete; and Numbers &operator=(const Numbers &) = delete;. Any copy is then a compile error (use of deleted function) instead of a double free at run time; passing by const& still works. Example: 2.4.forbid_copy/nocopy.cpp (README.txt).
  • A class whose members manage themselves (string, vector, int, other well-written classes) needs none of the three.
Coming from JavaJava assignment and parameter passing copy references; copying an object takes an explicit clone(). In C++, copying an object is the default, and you decide what a copy means.

Self-test (after the walkthrough)
  1. Buffer allocates data_ in its constructor, deletes it in its destructor, and has no copy constructor. What happens here? 
    Buffer a(10);
{
    Buffer b = a;
}
a.write("hi");
    Show answer

    b shares a's memory, and b's destructor frees it at the }. a.write then writes to freed memory (use after free), and a's destructor later frees it again (double free).

  2. Which of these call the copy constructor: IntArray b = a;, IntArray c(a);, IntArray d; d = a;, and f(a) where void f(const IntArray &)?
    Show answer

    The first two. d = a; calls operator= (d already exists), and passing by const& makes no copy.

  3. What does a = a; do with this operator=? 
    delete[] data_;
data_ = new int[other.capacity_];
for (...) data_[i] = other.data_[i];
    Show answer

    other is *this, so the loop copies from the array that was just deleted: use after free, and garbage values.

  4. Does a class whose only members are a string and an int need its own destructor, copy constructor, or operator=?
    Show answer

    No. Each member already copies and cleans up correctly, so the compiler-written versions are right.

  5. Which functions run for IntArray x = y;? For IntArray x; x = y;?
    Show answer

    The first: the copy constructor only. The second: the default constructor, then operator=.

Copying a linked chain

destructor, copy constructor, and operator= for a chain of nodes
Lecture

Deep-copying a chain

10 min

A linked container owns not one block of memory but a whole chain of nodes, so copying it means rebuilding the chain node by node. It's the rule of three again, applied to the structure you'll use most in CSS 342: linked stacks, queues, and lists all need a destructor, a copy constructor, and an operator= that handle every node. Keeping the order and handling the empty chain are where most of the bugs are.

  • A linked container owns every node. Its destructor must delete all of them, for example by popping until it's empty.
  • The copy must keep the order. Walking the original from the front and pushing each item reverses it. Instead, walk the original and append, keeping a pointer to the last node copied. Example: 3.1.copy_chain/copy_chain.cpp copies a three-node chain both ways, all in main (README.txt).
  • operator= = clear the current nodes + copy the other's, guarded against self-assignment. Put the shared work in private helpers (for example clear and copyFrom), used by the destructor, the copy constructor, and operator=.
  • Copies cost time and memory: one new per node. Pass containers by const&.
In your CSS 342 courseCarrano's LinkedBag, LinkedStack, and LinkedList each have exactly this copy constructor and a destructor that clears the chain. Graders test them by copying.

  1. A copy constructor walks other from the top and calls push for each item. other is (top first) 3, 2, 1. What is the copy?

    Show answer

    Leaks: only the top node is freed. The other three are lost (valgrind reports them as definitely or indirectly lost, depending on how they're reachable).

    The compiler-written copy would share the nodes. Popping the copy deletes nodes that the original still points to, and the original's destructor deletes them again.

  4. How many new calls does copying a 1000-item LinkedStack make?
    Show answer

    1000, one per node.

Exceptions and RAII

throw, try/catch, the standard exceptions, unique_ptr
Lecture

Throw, catch, and clean up

15 min

Some errors can't be handled where they're detected: a stack's pop doesn't know what its caller wants to do when the stack is empty. An exception carries the error up to code that does know, without every function in between checking a return value. Because an exception can cut a function short, C++ also needs a way to make sure memory is still released, and that is RAII: let destructors do the cleanup.

  • throw an object; the function stops right there, and the nearest enclosing try with a matching catch handles it. That try can be several calls up: the exception leaves every function between the throw and the catch at once, without finishing any of them or returning a value, and jumps straight to the catch. If no catch matches, the program calls terminate and aborts. Throw only for real errors: C++ lets you throw anything (even throw 42;), but using exceptions as an ordinary return or to get out of a loop is an abuse.
  • Standard exceptions (<stdexcept>) come in families: logic_error (a bug the caller could have avoided: invalid_argument, out_of_range, length_error) and runtime_error (problems the program couldn't prevent). All of them are kinds of exception, which has what(), the message.
  • Catch by const&, and list handlers from most to least specific: a handler for a family (logic_error, exception) catches every exception in it. Example: 4.1.throw_catch/throw_catch.cpp has main call average, which calls divide: when divide throws, average's "back from divide" line never prints, and the exception lands in main's catch. It also catches in order, ends with an exception nobody catches, and has a commented-out throw for a non-error to try (the abuse); see its README.txt.
  • Carrano's PrecondViolatedExcept is a logic_error; his ADTs throw it, for example from peek() on an empty stack.
  • Stack unwinding: as an exception leaves each scope, the destructors of that scope's local objects run. A raw new has no destructor, so it leaks.
  • RAII ("resource acquisition is initialization"): tie every resource to an object whose destructor releases it. IntArray and LinkedStack are RAII classes; unique_ptr does it for a single allocation: unique_ptr<int[]> p = make_unique<int[]>(n);. Example: 4.2.raii_unwinding/raii.cpp: a local object is destroyed on the way out, a raw new leaks, and a unique_ptr doesn't (README.txt, with valgrind's report).
Coming from JavaC++ has no checked exceptions and no finally. Cleanup happens in destructors (RAII), which run on every exit path, exception or not.

The exception families behind the catch order; stack unwinding and RAII, using raii.cpp; how the whole lab fits together: a class template that owns memory needs the rule of three, and RAII makes it exception-safe.

Self-test (after the walkthrough)
  1. Is this exception caught? try { throw out_of_range("x"); } catch (const logic_error &e) { ... }
    Show answer

    Yes: out_of_range is a kind of logic_error, and a handler for the family catches every exception in it.

  2. An exception is thrown three function calls deep and caught in main. What runs on the way?
    Show answer

    The destructors of every local object in each scope the exception leaves, innermost first (stack unwinding). Code after the throw in those functions does not run.

  3. What is lost by writing catch (exception e) (by value)?
    Show answer

    The exception is copied into a plain exception, losing the specific part (slicing), and the copy costs time. Catch by const&.

  4. Should a destructor throw?
    Show answer

    No. Destructors run during stack unwinding; if one throws while another exception is in flight, the program calls terminate. Destructors are implicitly noexcept in C++11 and later.

Takeaways

Learned
  • A template is written once and instantiated for each type; the type must support what the body uses, and the whole template lives in its header.
  • A class that owns memory needs the rule of three: destructor, deep-copying copy constructor, and operator= (or = delete copying). The compiler-written versions copy pointers, not what they point to.
  • operator= handles self-assignment, copies before it deletes, and returns *this. Deep-copying a chain means appending in order, one new per node. Pass containers by const&.
  • Throw standard exceptions, catch by const& from most to least specific, and rely on destructors (RAII, unique_ptr) for cleanup.
