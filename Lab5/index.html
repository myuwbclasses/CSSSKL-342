Lecture

vector, string, and files

20 min

You've built growable arrays by hand; now use the standard library's. vector and string manage their own memory, copy correctly, and know their size. Most programs also read their input from files and command-line arguments rather than the keyboard, and CSS 342 assignments are often run that way. Knowing how these classes behave (when a vector reallocates, which index operations are unchecked) keeps you from bringing back the bugs they were made to prevent.

  • vector<T> (Lab 4) is the growable array you built in Labs 3 and 4, done right: it knows its size(), grows with push_back, frees its memory in its destructor, and copies deeply.
  • size vs. capacity: when size() == capacity(), push_back allocates a bigger array (usually double), copies, and frees the old one. Pointers, references, and iterators into the vector are then invalid.
  • v[i] doesn't check the index; v.at(i) does and throws out_of_range (Lab 4). size() is unsigned: loop with a range-based for. Pass vectors by const&: by value copies every element. A 2D table is a vector of vectors: vector<vector<int>> t(3, vector<int>(4, 0));
  • string owns its characters and knows its size(); there is no '\0' to manage. s[i] and s.at(i) work as for a vector; + and += join; == and < compare the contents (unlike == on Java strings). s.substr(pos, len) copies a piece, and s.find("x") returns a position, or string::npos if it isn't there. to_string(42) and stoi("42") convert; stoi("abc") throws invalid_argument. Example: 1.1.string_basics/strings.cpp (README.txt).
  • Command-line arguments: int main(int argc, char *argv[]). argc counts the words on the command line, including the program's name in argv[0]. Check argc before using argv[1]; on an error, write to cerr and return 1;. Example: 1.2.argc_argv/args.cpp (README.txt).
  • Files: ifstream in(argv[1]); (<fstream>), then if (!in) to check that it opened. The right read loop tests the read itself: while (in >> value) for tokens, while (getline(in, line)) for whole lines. while (!in.eof()) is a classic bug: eof() turns true only after a read has already failed. Example: 1.3.read_loop/read_loop.cpp reads the same three-number file both ways and counts 3, then 4 (README.txt).
  • Taking a line apart: istringstream (<sstream>) turns a string into a stream, so >> reads its fields, skipping any amount of whitespace and converting each to its variable's type. Example: 1.4.parse_line/parse_line.cpp reads name age height lines and reports a bad one without stopping (README.txt).
  • Line endings: a file saved on Windows ends its lines with \r\n; Linux uses \n. >> treats the \r as whitespace, but getline keeps it at the end of the line. od -c file shows the actual bytes; VS Code's status bar shows CRLF or LF.
Coming from Javavector is ArrayList, but it holds the elements themselves (including ints, no boxing), and a vector variable is the vector: assigning one copies it. argv is Java's String[] args, plus the program name in argv[0].

Self-test (after the walkthrough)
  1. What do vector<int> a(3); and vector<int> b{3}; contain?
    Show answer

    a holds three zeros (the count constructor); b holds one element, 3 (the list initializer). Parentheses and braces mean different things here.

  2. int *p = &v[0]; v.push_back(7); cout << *p; What can go wrong?
    Show answer

    If push_back reallocated, p points into the freed old array: use after free. Any pointer, reference, or iterator into a vector may be invalidated by an operation that changes its size.

  3. A function takes vector<int> v by value and sorts it. Is the caller's vector sorted?
    Show answer

    No: the function sorted its own copy. Take vector<int> & to change the caller's vector (or const& to only read it).

  4. What does v.back() do on an empty vector?
    Show answer

    Undefined behavior: back(), front(), and [] don't check. Test empty() first.

  5. What does argc equal when you run ./words data/a.txt data/b.txt, and what is argv[2]?
    Show answer

    argc is 3 (the program name counts), and argv[2] is "data/b.txt".

  6. A file contains 10 20 abc 30. What does while (in >> x) read?
    Show answer

    10 and 20, then the read of abc fails and the loop stops; 30 is never read. Afterward in.fail() is true and in.eof() is false, which is how you know it stopped on bad data rather than at the end of the file.

  7. Your program matches if (line == "END") when you test on Windows, but never on Linux with the same input file. Why?
    Show answer

    The file has Windows line endings, so on Linux getline leaves a '\r' at the end of each line: line is "END\r". Strip a trailing '\r', or save test files with LF line endings.

Using and writing iterators

15 min

Containers store their elements in very different ways (an array, a chain of nodes, a tree), yet you want to visit them all with the same loop. An iterator gives every container one way to say "the current element" and "the next one", so the same code and the same standard algorithms work on all of them. Range-based for loops are iterators underneath, and the containers you write for CSS 342 often need one.

  • An iterator refers to one element and can move on: *it is the element, ++it moves to the next. begin() is the first element; end() is one past the last and is never dereferenced.
  • Every container has them, so the same loop works on a vector, a list, or a map. A vector's iterator is essentially a pointer (Lab 3); a list's wraps a node pointer. *it is * again, meaning "follow it", as in Lab 3's meanings of *.
  • auto lets the compiler work out a variable's type from its initializer: auto it = v.begin(); means vector<int>::iterator it = v.begin();. The type is still fixed at compile time (this is not a variable that can hold anything), so an auto variable must be initialized. Use it where the type is long (iterators) or has no name you can write (a lambda, Part 4); in a range-based for, const auto &x reads each element without copying it.
  • A range-based for is shorthand for a begin()/end() loop using !=, ++, and *.
  • Erasing while iterating: it = v.erase(it); (erase returns the next valid iterator); only ++it when you didn't erase.
  • const_iterator is read-only; it's what a const container gives you.
  • Writing one for your own container: a small class holding a Node*, with *, pre- and post-++, ==, and !=, plus begin() and end() on the container. Then range-for and standard algorithms work on it.

Examples: 2.1.same_loop_any_container/same_loop.cpp runs the same iterator loop over a vector, a list, and a string (README.txt); 2.2.pre_post_increment/increment.cpp writes ++c and c++ for a small Counter class and shows what each returns (README.txt). An iterator's ++ is written the same way.

Self-test (after the walkthrough)
  1. Why do generic loops test it != c.end() rather than it < c.end()?
    Show answer

    Only random-access iterators (vector, string, array) have <. List, map, and your own linked iterators only have == and !=, so != works for every container.

  2. What is wrong with this loop? 
    for (auto it = v.begin(); it != v.end(); ++it) {
    if (*it == 0) {
        v.push_back(1);
    }
}
    Show answer

    push_back may reallocate, which invalidates it (and end()), so the loop continues with a dangling iterator: undefined behavior. Collect what to add and append after the loop.

  3. Write the declaration of post-increment for an Iterator class.
    Show answer

    Iterator operator++(int);: it returns a copy (the old position) by value, and the unused int parameter marks it as postfix.

  4. What does *v.end() do?
    Show answer

    Undefined behavior: end() refers to one past the last element; there's nothing there.

list and map

linked lists, sorted key-value maps, choosing a container
Lecture

More containers

15 min

No one container is best at everything: a vector is fast to index but slow to insert into the middle, a linked list is the opposite, and looking items up by a key calls for something else again. The standard library has a container for each of these jobs, already written and tested. Choosing the right one, and knowing its traps (like map's [] quietly adding keys), is a skill you'll use in every larger program.

  • list is a doubly linked list: fast insert and erase anywhere (given an iterator), push_front, no []. It has its own sort(), remove(), and remove_if() members, because the general algorithms need random access or can't relink nodes.
  • map<Key, Value> stores key-value pairs sorted by key (a balanced binary search tree, CSS 343). Each element is a pair with .first (the key) and .second (the value).
  • m[key] inserts a default value if the key is missing. That makes counting easy, and makes "just looking" a bug. Use m.find(key) and compare with m.end() to look without inserting.
  • insert does nothing if the key already exists; it returns a pair whose .second says whether it inserted.
  • Choosing: vector by default; list for heavy middle insertion with no indexing; map for lookup by key in sorted order; unordered_map for faster lookup without order. The library also has set (sorted keys, no values) and stack and queue, which wrap another container and allow only the stack or queue operations.

Example: 3.1.map_lookup/map_lookup.cpp keeps phone extensions in a map<string, int>: [] and insert, find leaving the size alone, reading ext["Ravi"] adding Ravi, and the sorted loop over .first/.second (README.txt).

  1. map<string, int> m; if (m["x"] == 0) { } What is m.size() afterward?

Algorithms and lambdas

comparators, function pointers, lambdas and captures, erase-remove
Lecture

Passing behavior to algorithms

15 min

Sorting, searching, counting, and removing are written once in the standard library and work on any container through iterators, so you rarely need to write those loops yourself. What changes from one use to the next is the rule: sort students by name or by grade, count only the passing scores. C++ lets you pass that rule in as a function, and a lambda lets you write it right where you call the algorithm.

  • Algorithms (<algorithm>, <numeric>) work on iterator ranges: sort, find_if, count_if, remove_if, accumulate. Most take a function that customizes them.
  • A comparator returns true when a must come before b. Use <, never <=.
  • A function pointer passes a named function: using Compare = bool (*)(const Student &, const Student &);. The function's name converts to a pointer to it. Here * declares a pointer to a function: one more row for Lab 3's meanings of *.
  • A lambda is an unnamed function written in place: [](int a, int b) { return a > b; }. The [] lists captured local variables: [minId] copies one in, [&total] refers to one (& here means by reference, as in a reference declaration: see Lab 3's meanings of &).
  • accumulate's result has the type of its start value: start at 0.0 to sum doubles.
  • Erase-remove: remove_if only moves the kept elements forward and returns the new end; erase removes the rest.

Examples: 4.1.lambdas/lambdas.cpp sorts words with a named function and with a lambda, counts with a capturing lambda, and shows [x] vs. [&x] (README.txt); 4.2.erase_remove/erase_remove.cpp prints the vector after remove_if alone and after erase (README.txt).

Coming from JavaLambdas are like Java's (a, b) -> a > b, but you choose how local variables are captured, by copy or by reference, and a comparator returns bool rather than an int like compareTo.

Takeaways

Learned
  • vector and string are the defaults: pass them by const&, loop with range-for, and remember that growing can invalidate pointers and iterators.
  • Take the input file from argv after checking argc; check that it opened; read with while (in >> x) or while (getline(in, line)), never while (!in.eof()); split lines with istringstream; report errors on cerr with a nonzero exit code.
  • Iterators make every container look the same: begin() to end() with !=, ++, *. Give your own container an iterator and range-for and the algorithms work on it.
  • list for linked behavior, map for sorted lookup by key; m[key] inserts, find doesn't.
  • Pass behavior to algorithms with function pointers or lambdas; comparators use <; remove with erase-remove.
