Finding bugs

cout vs. cerr, gdb, the VS Code debugger
Lecture

cerr and the debugger

15 min

Your programs will crash or print wrong answers, and rereading the code is the slowest way to find out why. Two tools are faster: printing what the program is doing, in a way that doesn't mix with its real output, and a debugger, which stops the program at any line and shows every variable. C++ makes them more important than in Java, because a crash often comes with nothing but Segmentation fault and no stack trace.

  • Two output streams. cout is the program's real output: what a grader compares. cerr is for errors and debug messages. ./prog > out.txt sends only cout to the file; cerr still appears on the screen. (2> redirects cerr.) Example: 1.1.cerr_vs_cout/streams.cpp, with its output in README.txt.
  • cout waits; cerr doesn't. Text sent to cout can sit in a buffer and be written later (endl writes it right away). If the program crashes, whatever was waiting is lost, which is easy to miss because on a terminal it usually appears anyway. cerr is written immediately. Debug messages go to cerr. Example: 1.2.cout_lost_on_crash/crash.cpp prints with cout and no newline, then crashes: the message never appears. Its README.txt shows the output, and two fixes to try.
  • Compile with -g so the debugger knows file names, line numbers, and variable names. Every Makefile in this course uses it.
  • gdb, in the terminal (works everywhere, including over SSH). The essentials are below; the full list is in the gdb command reference, a separate page linked from every lab's left menu (Reference):
    CommandWhat it does
    gdb ./gradesStart gdb on a program (it doesn't run yet).
    runRun it. It stops at a breakpoint, or where it crashes.
    btBacktrace: which function you're in, and which line called it, all the way up to main. The first thing to type after a crash.
    break average
    break grades.cpp:13    		Stop when that function or line is reached.
    next / stepRun one line; step goes into a function call, next runs the call without stopping in it.
    print totalShow a variable, or any expression: print total / count.
    frame 1Look at the caller's variables (frame numbers come from bt).
    continue / finishRun to the next breakpoint / to the end of the current function.
    quitLeave gdb.
  • The VS Code debugger runs the container's gdb for you, with buttons and panes instead of typed commands. It comes from the C/C++ extension, which must be installed in the container (Pre-Lab step 7). Click left of a line number to set a breakpoint (a red dot). For a one-file program, with the .cpp file open, use the ▷ menu at the top right of the editor → Debug C/C++ File, or type Debug C/C++ File in the Command Palette (Ctrl+Shift+P). The first time, choose C/C++: g++ build and debug active file. Then F10 = next, F11 = step into, Shift+F11 = step out, F5 = continue; the Variables, Watch, and Call Stack panes show what print and bt would.
  • Which tool when: a crash: run it in the debugger and read bt. Wrong output: set a breakpoint before it goes wrong, step, and watch the variables until one isn't what you expected.
Coming from Javacout and cerr are System.out and System.err. The VS Code debugger works like IntelliJ's or Eclipse's. The difference: a crashed C++ program gives you no stack trace unless you run it in a debugger.

Classes in C++

.h/.cpp split, constructors, initializer lists, const member functions
Lecture

Writing a class

20 min

A class bundles data with the functions that keep it valid: if only Rational's own functions can set the denominator, it can never be zero. The ideas are the ones you know from Java, but C++ splits a class across a header and a .cpp file and adds details Java doesn't have, such as initializer lists and const member functions. Every CSS 342 assignment is built from classes written this way.

  • The class declaration goes in the header: data members and member function declarations. Member function definitions go in the .cpp, each prefixed with the class name: int Rational::numerator() const { ... }. Note the ; after the class's closing brace.
  • Access: public: and private: label whole sections, not single members. Data members are private.
  • Constructors have the class's name and no return type. You can overload them. Initialize members in the initializer list, which runs before the body: 
    Rational::Rational(int num, int den) : num_(num), den_(den) {
    normalize();
}
    The older way you'll also see: assigning the members inside the constructor body. Much existing code (and many textbook and online examples) is written like this, and it still works: 
    Rational::Rational(int num, int den) {
    num_ = num;      // assignment, not initialization
    den_ = den;
    normalize();
}
    For int members, both versions give the same result. But the initializer list is the proper way, and the one to write: the members are created with their values, instead of being created first and assigned afterward (for members that are themselves objects, that means doing the work twice). Some members can't be assigned at all: with a const member, the body version fails with error: assignment of read-only member, and only the initializer list compiles. So read the old style when you meet it, and write initializer lists in your own code.
  • Members are not initialized for you. An int member you forget holds garbage, not 0.
  • const member functions promise not to change the object: int numerator() const;. A const object, or a const& parameter, can only call const member functions. Mark every function that doesn't change the object as const.
  • Creating objects: Rational r(1, 2); or Rational r; for the default constructor. Not Rational r();, which declares a function.
  • struct is the same as class, except members are public by default.
Coming from JavaNo new: Rational r(1, 2); creates the object right there, as a local variable, and it is destroyed at the end of the scope. Java's Rational r = new Rational(1, 2); corresponds to pointers and new, which come later.

Object lifetime

scope, destructors, copies, member order, returning references
Lecture

Birth and death of objects

15 min

In Java an object lives until the garbage collector decides it's unreachable, and you never know exactly when. In C++ an object dies at a precise moment, usually a closing }, and its destructor runs right then. That is what lets a C++ class release memory and other resources on time, and it means you need to know exactly when your objects are created, copied, and destroyed.

  • Local objects are created at their definition and destroyed at the end of their scope (the closing }), in reverse order. Globals are created before main and destroyed after it. Example: 3.1.scope_and_destructor/scope.cpp creates objects in main and in a { } sub-block inside it, and every constructor and destructor prints; predict the order, then check its README.txt.
  • The destructor ~Tracer() runs automatically when an object dies. It's where a class releases what it owns (memory it allocated, for example). There's no garbage collector.
  • The copy constructor Tracer(const Tracer &other) runs whenever a new object is made as a copy of another: Tracer t1(t2);, Tracer t1 = t2;, pass by value, and sometimes return by value. Passing by const& makes no copy.
    Tracer t1 = t2; is copy construction, not assignment, even though it has an =: the line declares t1, so a new object is being created, and that is always a constructor's job. It means exactly the same as Tracer t1(t2);. Only t1 = t2; on an object that already exists is assignment. Example: 3.2.copy_construction/copy.cpp prints which one runs for each form; see its README.txt.
  • Copy elision: when returning a local by value, the compiler usually builds it directly in the caller's variable, so no copy happens. Example: 3.3.copy_elision/elision.cpp returns a local Tracer and shows only one object being made; built again with -fno-elide-constructors, the copy it saved reappears. See its README.txt.
  • Members are constructed in the order they are declared in the class, whatever order the initializer list uses, and destroyed in reverse.
  • Returning references from members: provide two versions, a non-const one that returns T& (can be assigned) and a const one that returns T or const T& (read-only). The compiler picks by the object's constness: a non-const object calls the non-const version, a const object (or a const& parameter) calls the const version. Whether you read or write doesn't matter. 
    class Counter {
public:
    int &value()       { return count_; }   // version 1: non-const
    int  value() const { return count_; }   // version 2: const
private:
    int count_ = 0;
};

void show(const Counter &k) {
    cout << k.value();            // k is const here      -> version 2
}

Counter c;                       // c is NOT const
c.value() = 4;                   // -> version 1: returns c's count_ itself, so it becomes 4
int n = c.value();               // -> version 1 too: c is not const (n is 4)
show(c);                         // inside show, k is const -> version 2

const Counter fixed;             // fixed IS const
int m = fixed.value();           // -> version 2 (m is 0)
fixed.value() = 9;               // error: version 2 returns a copy of the int:
                                 //        lvalue required as left operand of assignment
Coming from JavaJava objects live until the garbage collector decides; finalize may never run. A C++ destructor runs at a known moment, every time, which is what makes C++'s style of memory management possible.

Operator overloading

member vs. non-member, return types, <<, friend
Lecture

Operators are functions

15 min

A class for fractions, money, or dates is easier to use when a + b, a < b, and cout << a work just as they do for int. C++ lets you define what operators mean for your own types, and the standard library counts on it: sorting and map use <, and printing uses <<. CSS 342 assignments regularly ask for ==, <, and << on your classes.

  • a + b calls operator+(a, b) (non-member) or a.operator+(b) (member). You choose which to write; the same operator+ can be declared either way: 
    class Money {
public:
    Money operator+(const Money &rhs) const;              // member: inside the class,
};                                                        //   ONE parameter (the right operand)

Money operator+(const Money &lhs, const Money &rhs);    // non-member: a GLOBAL function,
                                                        //   outside any class, TWO parameters
    Write one or the other, not both. A non-member operator is an ordinary global function, the same kind as celsiusToFahrenheit in Lab 1; it belongs to no class, so it can only use the class's public members (unless the class makes it a friend). Either way, a + b is just a shorter way to call that function. -, *, and / work the same way. Example: 4.1.member_vs_nonmember_operator/operators.cpp calls operator+ both ways and prints which function ran, with the non-member version ready to swap in; see its README.txt.
  • Signatures to copy:
    OperatorWrite it asReturns
    +=, *=, =memberT& (return *this;)
    +, -, *non-member, const T& parametersT by value (a new object)
    ==, !=, <non-memberbool
    <<non-member: the left operand is the streamostream& (the same stream)
    []member, const and non-const versionsT& / const T&
  • return *this; Inside a member function, *this means "the current object": the one the function was called on (t in t += a). Returning it by reference is what lets (t += a) += b and a = b = c work. For now, read *this as one phrase; the * is explained when you learn pointers. Example: 4.2.return_this/return_this.cpp runs (total += a) += b and gets 123; with += returning by value instead, the second += changes a copy and total ends up 120. See its README.txt.
  • Build operators from each other: + from +=, != from ==, > from <. Then the logic lives in one place. Example: 4.3.operators_from_each_other/build_from.cpp builds + from += and != from ==; see its README.txt.
  • Why non-member +? A constructor that takes one int converts 2 into a Rational automatically, but only for function arguments, not for the object a member is called on. As a non-member, both half + 2 and 2 + half work. 
    // + as a MEMBER                             // + as a NON-MEMBER
m + 2    // m.operator+(2): works           n + 2    // operator+(n, 2): works
2 + m    // 2.operator+(m): ERROR, an int   2 + n    // operator+(2, n): works too,
         //   has no member functions                //   2 is just an argument
    Example: 4.4.why_nonmember/why_nonmember.cpp has two otherwise identical classes, one with each kind of +, and a line to uncomment that shows the real error: no match for 'operator+' (operand types are 'int' and 'MemberMoney'). See its README.txt.
  • friend, and operator<<. operator<< is always a non-member (its left operand is the stream), so like any outsider it can only use the class's public members. Two cases: 
    // 1. The class has public accessors: no friend needed.
class Point {
public:
    int x() const { return x_; }
    int y() const { return y_; }
private:
    int x_, y_;
};
ostream &operator<<(ostream &out, const Point &p) {     // a global function
    return out << "(" << p.x() << ", " << p.y() << ")";
}

// 2. No accessors: the class grants friendship to that ONE function.
class Secret {
public:
    friend ostream &operator<<(ostream &out, const Secret &s);   // declaration only
private:
    int code_;
};
ostream &operator<<(ostream &out, const Secret &s) {    // still a global function:
    return out << "Secret #" << s.code_;                // no "friend", no "Secret::"
}
    The friend line inside the class only says "this global function may use my private members". It does not make it a member: the definition is an ordinary global function, written without friend and without Secret::. Use friend only when public accessors aren't enough. Example: 4.5.friend_operator_output/friend_output.cpp has both classes with one driver; its README.txt shows the output and the real errors for the three usual mistakes: leaving out the friend line, writing friend on the definition, and writing Secret:: on it.
Rational &Rational::operator+=(const Rational &rhs) { ...; return *this; }
Rational operator+(const Rational &a, const Rational &b) { Rational r = a; r += b; return r; }
ostream &operator<<(ostream &out, const Rational &r) { return out << r.toString(); }

Self-test (after the walkthrough)
  1. Card has private rank_ and suit_ and no accessors. How do you declare a non-member operator== that can read them?
    Show answer

    Declare it as a friend inside the class: friend bool operator==(const Card &a, const Card &b);, then define it outside as a normal function (without the word friend).

  2. You write + as a member: Rational operator+(const Rational &rhs) const;. Which of half + 2 and 2 + half compile?
    Show answer

    Only half + 2 (it's half.operator+(Rational(2))). For 2 + half there's no member function to call on an int, and the left operand of a member call is never converted.

  3. What is wrong with this? 
    Rational &operator+(const Rational &a, const Rational &b) {
    Rational r = a;
    r += b;
    return r;
}
    Show answer

    It returns a reference to the local r, which is destroyed when the function returns. + must return by value: Rational operator+(...).

  4. Why does cout << a << b; only work if operator<< returns the stream?
    Show answer

    It's evaluated as (cout << a) << b: the result of the first call is the left operand of the second, so it must be the stream itself (by reference; streams can't be copied).

  2. In each subfolder, run make clean. Delete any other .o files, executables, and out.txt.
  3. Delete the examples folder (Lab2/examples/): it holds the lecture examples, and you didn't change anything in it. Your zip should contain only exercises/.
  4. Check that everything compiles with g++ -std=c++17 -Wall -Wextra on Linux. The only warning allowed is the -Wreorder warning in lifetime.cpp, which is there on purpose.
  5. Create one zip file of the whole Lab2 folder, named Lab2-<your UW NetID>.zip (from the folder above it: zip -r Lab2-netid.zip Lab2).
  6. Upload that one zip file to the Lab 2 assignment on Canvas.

Takeaways

Learned
  • Debug messages go to cerr, real output to cout. After a crash, run it in the debugger and read bt; for wrong output, set a breakpoint and step.
  • Declare the class in the header, define members in the .cpp, initialize every member in the initializer list, and mark every function that doesn't change the object const.
  • Objects die at the end of their scope, in reverse order, and their destructor runs every time. Pass by value makes a copy; const& doesn't.
  • Compound operators are members returning *this (the current object) by reference; arithmetic and comparison operators are non-members; << returns the stream.
