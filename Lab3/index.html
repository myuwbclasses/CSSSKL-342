Pointers

addresses, dereferencing, nullptr, pointers to structs, the jobs of & and *
Lecture

Addresses and pointers

25 min

Java hides addresses: every object variable is a reference the language manages for you. C++ lets you hold an address yourself, in a pointer, and that is how you reach memory you allocate while the program runs and how you build structures that grow and change shape, such as linked lists and trees. Pointers are also the most common cause of C++ crashes, so it pays to be exact about what & and * mean.

  • A pointer holds an address. int *p = &a;: &a is "the address of a", and p stores it.
  • Dereference with *: *p is "the int that p points to". *p = 7; changes a.
  • nullptr means "points at nothing". Dereferencing it crashes the program (Segmentation fault); gdb's bt shows the line (After a crash). An uninitialized pointer is worse: it points somewhere random.
  • Pointers to structs and objects: p->x is short for (*p).x.
  • Pointer or reference parameter? Both let a function change the caller's variable. Use a reference unless "nothing" (nullptr) is a valid value, or the pointer itself must be moved to point elsewhere, as in linked nodes.
  • Spacing doesn't matter: int *p, int* p, and int * p are the same. This page writes int *p, with the * next to the name, as Carrano does; the next bullet shows why.
  • In int* p, r;, what type is r? A plain int, not a pointer. The * belongs to the name right after it, not to the type, even though writing int* p makes it look that way, so the line means int *p; int r;. Try r = &a; and g++ says invalid conversion from 'int*' to 'int'. For two pointers write int *p, *r;, or better, declare one pointer per line.
int a = 5;
int *p = &a;          // p holds a's address
int *q(&a);           // the same, initialized with ( ): q also holds a's address
*p = 7;               // a is now 7 (so *q is 7 too)
int *none = nullptr;  // points at nothing
Point pt = {1, 2};
Point *pp = &pt;
pp->x = 10;           // same as (*pp).x = 10
Coming from JavaEvery Java object variable is secretly a pointer: Node n = head; copies an address, and null is nullptr. C++ makes that explicit, lets you point at any variable (including ints), and lets you get it wrong.

& and * at a glance: one symbol, several jobs

The rule that sorts most of it out: in a declaration (where a name is introduced: a variable, a parameter, a return type), & means reference and * means pointer. In a statement (code that runs), & means the address of and * means follow the pointer. The two tables below line them up. Both assume:

DataType aVar(proper_value);   // properly initialized
DataType *aPtr(&aVar);         // properly initialized: aPtr points to aVar

    9. pp points to p, so *pp is p, and **pp is *p, which is x.

Arrays

one contiguous block of memory: no length, no bounds checking, pointer arithmetic
Lecture

Arrays are memory

15 min

An array is the simplest and fastest container: elements side by side in memory, each reached by its index in one step. Underneath vector, string, and the array-based containers you'll write for CSS 342 is a plain C++ array. Unlike a Java array, it carries no length and checks no index, so knowing what it is in memory is how you avoid writing past its end.

  • An array is one contiguous block of elements, side by side. int a[8]; sets aside 8 × 4 = 32 bytes, and that's all it is: no length stored anywhere, and no check on the index you use. The size must be a constant; a size known only at run time needs new[] (Part 3).
  • The array's name is the address of its first element. Used in an expression, a becomes &a[0], so int *p = a; works. (One difference: sizeof(a) is the whole block, 32, while sizeof(p) is the size of an address, 8.)
  • Indexing is pointer arithmetic: a[i] is defined as *(a + i), and p + 1 moves one element (4 bytes for an int), not one byte. You can walk an array with a pointer: for (int *q = a; q < a + 8; q++).
  • An index can be negative. p[i] means *(p + i) for any pointer, so from int *p = &(a[5]);, p[-2] is a[3]. Negative indexes only make sense from a pointer into the middle; a[-1] is outside the array. Example: 2.1.index_is_pointer_arithmetic/index.cpp shows both, with its output and a picture in README.txt.
  • Bounds are not checked or protected. a[8] and a[-1] compile and run: reading gives whatever happens to be there, and writing silently overwrites a neighbor. No exception, no message, and for a local array like this one, not even valgrind notices.
  • Passing an array passes only its address. void f(int values[]) means exactly void f(int *values): the function can't know the length, so always pass a count too.
  • Arrays of objects: Point pts[3]; creates three real Point objects, side by side, the moment the array is created; elements without an initializer get the default constructor. pts[1] = Point(7, 8); sets an element. Example: 2.2.array_of_objects/objects.cpp prints every constructor call; see its README.txt.
  • 2D arrays: int a[2][3]; is 2 rows of 3 ints, stored as one block of 6 ints, row after row. Set them with int a[2][3] = {{1, 2, 3}, {4, 5, 6}}; or one at a time, a[1][2] = 60; (row 1, column 2), and walk them with nested loops. A pointer to pointer, int **p, is a different layout: p points to a pointer, which points to the actual ints. So int **p(a); does not compile (a holds ints, not pointers), but with an array of row pointers in the middle, it does: 
    int *rows[2] = {a[0], a[1]};   // one pointer to the start of each row
int **p(rows);                 // legal: p points to rows[0]

  +-----+          +-----+            +----+----+----+

⚠ Warning: C++ does not check array boundsWith int b[4];, the valid indexes are 0 to 3. Yet b[4] = 10; and b[-1] = 5; compile without a warning and run without a crash: they silently overwrite whatever memory is next to b. The damage may show up much later, somewhere else, or never in your tests and then in the grader's. Keeping every index between 0 and size − 1 is your job. Example 2.1 does exactly this; see its README.txt.
Coming from JavaA Java array is an object that knows its length and checks every index (ArrayIndexOutOfBoundsException). A C++ array is just the elements: you carry the length yourself, and a bad index is your bug to find. And Java's new Point[3] makes three null references, while C++'s Point pts[3]; makes three Point objects.

Dynamic memory

the heap, new/delete, arrays sized at run time, valgrind
Lecture

The heap: new and delete

15 min

A local variable dies at the end of its scope, and a local array's size must be known when you compile. Many programs need memory whose size is only known at run time (room for every line of a file) or that must outlive the function that made it (a node added to a list). The heap provides that memory, but in C++ you, not a garbage collector, decide when it's released, and valgrind checks that you got it right.

  • Locals live on the stack and die at the end of their scope. new allocates on the heap, and the memory lives until you delete it, whatever scope you're in.
  • Pairs must match: new with delete, new[] with delete[]. Exactly once each.
  • Two examples: 3.1.new_and_delete/new_delete.cpp puts an array on the stack, an int and a Point on the heap, and arrays on the heap, initialized three ways (new int[4]{10, 20, 30, 40}, new int[n]() for zeros, and new int[n], garbage until set); passes them to functions; and releases them in main or inside a function. 3.2.dangling_and_leak/mistakes.cpp creates a dangling pointer and two leaks. Each README.txt (and this one) has the output and what valgrind says.
  • Arrays sized at run time: int *a = new int[n]; with any n, even one the user typed. a points to the first element, and a[i] works exactly as in Part 2. A function can return such an array: it stays alive until someone delete[]s it, so the caller must know it now owns it.
  • Growing an array (an array can't change its size; Carrano's resizable bag does this): allocate a bigger array, copy, delete[] the old one, and re-point.
  • After delete, set the pointer to nullptr. Deleting nullptr is harmless; deleting twice is not.
  • The classic bugs: leak (no delete), double delete, use after delete, delete vs. delete[] mismatch, reading past the end. Most of them look fine when you run the program. valgrind finds them in heap memory (unlike the overrun inside a local variable in Exercise 2, TODO 6): 
    valgrind --leak-check=full ./program
Coming from JavaJava's garbage collector frees objects once nothing refers to them. In C++, every new needs a matching delete that you write, or the memory is lost until the program ends.

    void process() {
    int *buffer = new int[100];
    if (!loadData(buffer)) {
        return;

    use(buffer);
    delete[] buffer;

Linked nodes

building, walking, changing, and freeing a chain
Lecture

Chains of nodes

15 min

An array is one fixed block, so growing it or inserting in the middle means moving or copying everything. A chain of nodes linked by pointers grows one node at a time, and inserting anywhere means changing just a couple of pointers. The linked stacks, queues, lists, and trees in CSS 342 are all built from such nodes, so these pointer patterns come back in almost every assignment.

  • A node holds an item and a pointer to the next node. The last node's next is nullptr. A chain is reached through one pointer, head; an empty chain has head == nullptr.
  • Walking a chain: for (const Node *cur = head; cur != nullptr; cur = cur->next). Every linked-structure traversal you'll write for CSS 342 is this loop.
  • Changing the chain means changing pointers. A function that can change which node is first takes Node *&head.
  • Removing a node: find the node before it, re-link around it, then delete it. Removing the first node is a special case: it changes head.
  • Freeing a chain: save next before deleting the current node.
  • Always check three cases: empty chain, one node, many nodes. And draw boxes and arrows before writing code.

Two short examples, everything in main on a hard-coded chain of three nodes, 10 → 20 → 30, with a drawing of each step in their README files:

  • 4.1.build_and_walk/build_walk.cpp (README.txt): build the three nodes and link them, walk the chain with a while loop, and free it.
  • 4.2.change_and_remove/change_remove.cpp (README.txt): remove the second node, remove the first node (where head has to move), and add a node at the front.
In your CSS 342 courseCarrano's LinkedBag, LinkedStack, and LinkedList use a Node class template with getItem() and getNext(), but the pointer work is exactly what you do here.

    last is nullptr, so last->next dereferences nullptr: a segmentation fault. Handle the empty chain first.

  4. How many new and delete calls does it take to build a 5-node chain and free it?
    Show answer

    Five of each: one new per node, and deleteChain deletes each node once.

Takeaways

Learned
  • A pointer holds an address: & takes one, * follows one, -> reaches a member. Initialize every pointer, and never follow nullptr.
  • In a declaration, & is a reference and * a pointer; in a statement, & is "address of" and * "follow the pointer". Between two values they are bitwise AND and multiplication, and && is logical AND (tables).
  • An array is one contiguous block with no length and no bounds checking: a[i] is *(a + i), an index can even be negative from a pointer into the middle, and a bad index fails silently. Pass the count with every array.
  • Every new needs one delete, every new[] one delete[]. Run valgrind on everything: memory bugs usually look fine until they don't.
  • Linked structures are pointer rewiring: draw it, handle the empty and first-node cases, and save next before you delete.
